# 2026-10-31 — HN pipeline 成本优化

## 背景

GitHub Actions 从 2026-10-30 起连续失败。Actions 日志确认 HN API 抓取正常，失败发生在 OpenAI 摘要阶段：API 返回 `429` / `You have no credits remaining`。历史日志显示该 pipeline 每月约花费 $1.60–$1.78。

## 本次调整

- 删除 `.github/workflows/hn_best.yml`，停止每日 Best Stories 自动任务；历史 Best JSON、Markdown 页面和 `main.py best` 手动模式全部保留。
- `hn_top.yml` 从每天五次改为每天两次：15:00 UTC 和 03:00 UTC，约对应洛杉矶冬令时 7 AM / 7 PM、夏令时 8 AM / 8 PM。
- 修复标签重复计费：过去只要当天 JSON 中出现一篇新文章没有 tags，就会把全部 50–100 篇文章重新交给 GPT 分类。现在只提交缺少/空 tags 的文章；已有文章保留原 tags，仅运行不调用 API 的本地关键词补充。
- 保留 `force=True` 的全量重新分类语义。
- 新文章不再只凭标题和 URL 生成摘要。抓取源页面时复用原本的图片请求，提取临时正文上下文；过滤导航、广告、Cookie、订阅、推荐和分享区域，只取网页描述和开头最多两个有效正文段落，并将每篇硬限制为 1,200 字符。HN self-post 优先使用 HN 自带正文。正文不会写入 JSON。
- 摘要调整为上下文足够时 3–4 句：前 2–3 句只总结事实，最后最多 1 句说明来源支持的重要性，不允许个人评价；上下文不足时宁可减少句数也不猜测。
- 抓取按单条隔离：超时、付费墙、非 HTML、解析异常或空正文均降级到原来的标题模式，不影响其余文章和整批任务。标题模式只生成 1–2 句能够由标题直接支持的内容。单页 HTML 下载最多 512 KiB，避免异常大页面造成无上限流量或内存消耗。

## 验证

- GitHub Actions YAML 可正常解析。
- `tag_generator.py` 通过语法编译。
- 使用 3 篇文章的离线临时 JSON 测试：2 篇已有 tags、1 篇无 tags，模型替身只收到无 tags 的 1 篇；已有的 `AI` 和 `Security` 标签未被覆盖。
- 抽样最近 8 个来源页：4 个成功提取，共 2,408 字符（按 4 字符/token 保守估算约 602 input tokens，摊到全部 8 条平均约 75 tokens/条），4 个因付费墙、反爬或页面结构返回空上下文；成功样本未发现常见广告、Cookie、newsletter、subscribe 或 related-article 噪声。另用离线 fixture 验证第三个正文段落不会进入 prompt，1,200 字符硬上限有效。
- `git diff --check` 通过。

## 模型调研结论

当前 `gpt-5-nano` 价格很低，但已进入 deprecated 状态。后续候选优先考虑 `gemini-2.5-flash-lite`：付费价格为 $0.10/M input、$0.40/M output，支持 structured outputs，且有 OpenAI SDK 兼容入口。正式切换前需要用实际 HN 样本比较中英文摘要质量和 JSON 成功率，并将 provider/key/base URL 做成显式配置；本次没有切换供应商或提交任何新 key。

用户为现有 OpenAI API account 充值后，摘要主模型已配置为
`gpt-5.6-luna`。标签模型暂时保留 `gpt-5-nano`，以便单独观察摘要模型的
质量与成本变化。`token_logger.py` 同步加入 Luna 官方标准价格：input
$0.20/M、cached input $0.02/M、output $1.20/M。

首次生产测试（Actions #1272）中 Luna 一次成功处理 49 篇：摘要调用
9,355 input / 8,567 output tokens，估算 $0.012151；包含标签的整次运行为
$0.015751。正文可用的摘要事实密度明显改善。约 10/50 条正文不可用或上下文
过少的条目出现了 “The title identifies…” / “The supplied context…” 等元话语，
因此进一步收紧 title-only prompt，要求直接陈述主题且禁止提及 title/context。

首页 `Today's Top Stories / 今日头条` 标题现在显示其实际来源数据日期，
例如 `Oct 31, 2026`。日期取自最新 Top Stories JSON 的 `content_date`，而
不是访客浏览器时间，避免跨时区或部署延迟时显示错误日期。
